ACE Studio

ACE stands for Automated Computer Engineering. The studio above is a drag-and-drop editor for the documents that work with AI agents is written in: system prompts, specs, tool definitions, permission rules, loop prompts, workflow specs, task briefs, role cards, mandate letters. It grew out of Prompt Engineering Studio, which covers the first of those, and it adds seven more layers of templates down the left side.

The eight layers

The layers are ordered by how much each one contains. A prompt sits inside a context, a context inside a harness, and so on up to a holding of several organisations. The list reflects the field as it stood in October 2026.

  1. Prompt: one model call. Twelve blocks: Role, Context, Task, Constraints, Think Step-by-Step, Output Format, Few-Shot Examples, Self-Verify, Tone & Style, Grounding, Uncertainty and a plain Separator.
  2. Context: what the model is given. Three spec documents (requirements, design, tasks), three steering files (product, tech, structure), and seven blocks for agent skills, from the folder layout of a skill to a checklist for shipping one.
  3. Harness: one agent and its tools. Agent instructions, a tool definition, permissions, hooks, a subagent, MCP servers, a sandbox, a memory policy and a definition of done.
  4. Loop: one agent, many turns. The iteration prompt, a plan file, a progress file, a verification gate, stop conditions, pacing, a protocol for an agent that is stuck, and a handoff note.
  5. Graph: agents wired in fixed steps. A workflow spec, a node contract, shared state, a router, fan-out and fan-in, a verifier node, a human gate, and rules for retry and fallback.
  6. Fleet: many agents in parallel. A manifest, a task brief, a work queue, isolation and merge rules, budgets and limits, a status report, monitoring, and a kill switch.
  7. Organisation: agents arranged as a company. A charter, a role card, an org chart, decision rights, an escalation path, an operating cadence, a policy, a performance review and an onboarding pack.
  8. Holding: several organisations under one owner. A portfolio map, a mandate letter, budget and compute allocation, shared services, a contract between two organisations, governance and audit, a risk register with circuit breakers, and checklists for starting an organisation and closing it.

How to use it

Click a layer's name on the left to open it. Drag a template into the editor and it lands as an editable block with starter text already in it. Anything written in [CAPITALS] becomes a chip: click it, type the real value, and the chip is replaced. Each template has a small ? that explains what the document is for.

Blocks from different layers can sit in one document, and you can write blocks of your own, with a label, an emoji, a colour and a body. The custom library saves to a blocks.json file on your own disk and loads back; a blocks.json saved from Prompt Engineering Studio loads here too. Finished documents export as .prompt JSON, a Python string, OpenAI or Anthropic messages JSON, Markdown or plain text. A skill written with file boundaries exports as a folder packed into a .zip.

How settled each layer is

The templates in the first three layers follow formats that tools already read: system prompts, spec and steering files, skill folders, tool schemas, permission and hook settings, MCP server lists. You can often paste them where they are going with few changes.

Loop, Graph and Fleet are in everyday use, but the file names and fields differ from one tool to the next. Treat those templates as a list of what such a document needs to answer, and rename the fields to match your own setup.

Organisation and Holding are the least settled. Their templates borrow the documents a company uses to organise people (a charter, role cards, decision rights, a mandate letter, an audit plan) and apply them to agents. They are a starting structure to adapt, and the Holding layer in particular is still an open question.

What it does not do

It does not run anything. There is no model behind this page and no API key to paste in. You assemble a document here and take it to the tool you already use.

The health score and the hallucination badge are carried over from Prompt Engineering Studio and read only the blocks of the Prompt layer. A fleet manifest or a role card will score low on them, and that says nothing about the manifest or the card.

What you write stays in your browser's local storage and in files you choose yourself. There is no account. One feature talks to another server: Open from Bitbucket reads skill files from a Bitbucket Cloud repository you name, straight from your browser, with the access token you give it. The token is kept in local storage only if you tick the box that says so. There is a privacy note for the whole site.
